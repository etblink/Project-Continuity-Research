# Cross-Discipline Synthesis 0.1.0

Date: 2026-09-20  
Status: Research checkpoint before competing architecture design.

## Bottom line

The external comparison did **not** invalidate the empirical taxonomy.

Instead it produced three outcomes:

1. several failure classes have strong mature analogues;
2. current LLM-agent research is independently converging on the long-horizon
   context/planning problem;
3. the specific combination of authority, scoped supersession, negative
   knowledge, guarded promotion, human purpose, and succession still appears
   under-integrated.

## Most important change to the Project Kernel hypothesis

Earlier we sometimes spoke as though the Project Kernel might itself become
the canonical project memory.

The external comparison makes that look too dangerous.

Event-sourcing/provenance ideas suggest a cleaner role:

```text
DEEP DURABLE HISTORY / EVIDENCE / AUTHORITY
        ↓
CURRENT-STATE DERIVATION
        ↓
PROJECT KERNEL / ORIENTATION PROJECTION
        ↓
EXECUTION CONTRACT
        ↓
WORK
        ↓
VERIFIED RESULT
        ↺
```

The kernel is therefore increasingly best understood as:

> **a compact, auditable, regenerable orientation surface**

rather than:

> a compressed encyclopedia or sole source of truth.

That distinction directly attacks the risk that the continuity mechanism
itself becomes stale.

## Second major change

The research subject is not adequately described as "long-term memory for AI."

The broader object is:

> **externalized executive continuity for long-horizon human–AI work.**

Memory is one component alongside:

- intent;
- authority;
- state;
- provenance;
- transitions;
- constraints;
- review;
- succession.

## Third major change

"Reflection" should not be treated as a magic safety layer.

The empirical corpus and self-correction literature both point toward:

```text
reflection
+ reliable external feedback
+ explicit verification
```

being substantially stronger than:

```text
reflection alone
```

This gives the provisional concept **reorientation surface** a firmer footing.

## Fourth major change

The unnamed third philosophical/architectural concern has become harder to
ignore.

Logos asks:

```text
WHAT IS TRUE / JUSTIFIED?
```

Agape asks:

```text
WHAT / WHOM DOES THIS SERVE?
```

The corpus repeatedly asks a third question:

```text
GIVEN WHAT IS TRUE AND WHAT WE SERVE,
WHAT MAY / SHOULD BE CONCLUDED OR DONE NOW?
```

Engineering analogues exist in:

- state-transition guards;
- command authority;
- safety control actions;
- mission-command limits;
- authorization gates.

We still should **not name this as a first principle yet**. But it now has
cross-domain support as a distinct dimension.

## Novelty caution

We should not claim that the overall system is novel merely because no single
source in this review uses our vocabulary.

Before any public originality claim, a later pass should search specifically
for:

- workflow/provenance systems for scientific agents;
- autonomous-agent governance protocols;
- process-aware knowledge graphs;
- policy-as-code for agent transitions;
- durable multi-agent orchestration systems;
- long-running coding-agent state protocols.

For now the appropriate statement is:

> The **integrated combination** we require was not found as a mature standard
> in this first review.

## Next step

We have now earned the right to design **competing architectures**.

The next phase should not produce one favored kernel.

It should produce at least four candidates, for example:

1. document-centric orientation kernel;
2. event-sourced state + materialized kernel;
3. typed state-machine / policy-gate architecture;
4. provenance/evidence graph hybrid.

Each candidate should be evaluated against the same fifteen requirements and
the same historical adversarial incidents.

Only then should we choose a prototype.
