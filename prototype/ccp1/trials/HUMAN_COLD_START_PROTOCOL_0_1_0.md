# CCP-1 Human Cold-Start / Usability Protocol 0.1.0

Date: 2026-09-20  
Status: **FROZEN TRIAL PROTOCOL**

## Objective

Test whether a person who did not invent CCP can orient to the project without
becoming dependent on the inventor as a permanent executive-function layer.

This is a usability and comprehensibility trial, not a test of Git expertise.

## Participant requirement

Prefer a participant who:

- has not followed the Project Continuity Research work;
- has not read the design conversation;
- is comfortable reading ordinary technical prose;
- is not coached about the expected answers.

Record any prior familiarity.

## Allowed material

The participant receives:

1. the public repository;
2. the exact frozen trial Git ref;
3. this protocol.

They may use ordinary GitHub navigation/search.

They should not receive an oral project summary before beginning.

## Suggested timebox

Use approximately 30 minutes for the first unaided orientation attempt.

The participant may stop earlier if confident.

Record the actual time.

## Tasks

Without coaching, ask the participant to determine:

1. In their own words, what problem is this project trying to solve?
2. What phase is the project currently in?
3. What has to happen before the next major phase may begin?
4. Is the current CCP architecture already authorized to control a live
   project? Why or why not?
5. Where would they look to distinguish:
   - big-picture roadmap;
   - exact current research result;
   - machine verification;
   - historical research artifacts?
6. Pick one completed adversarial attack and explain:
   - what failure it was testing;
   - what passed;
   - what the result still does **not** prove.
7. What would they do next if asked to continue the project without the
   inventor present?
8. Name anything they found confusing, redundant, hard to locate, or easy to
   misinterpret.

## Assistance rule

During the first attempt, the facilitator may help only with mechanical access
problems.

If the participant asks a substantive question, record the question before
answering it after the unaided phase.

Those questions are product/research evidence.

## Observations to record

Record:

- elapsed time;
- first file opened;
- navigation path if practical;
- incorrect assumptions;
- points of hesitation;
- substantive questions;
- whether the roadmap helped;
- whether exact state could be distinguished from orientation prose;
- whether the participant found the current boundary without coaching.

## Automatic critical failures

The trial records a critical failure if the participant concludes that:

- live project mutation is currently authorized;
- CCP-2 is already authorized;
- CCP is frozen as the final universal architecture;
- a machine test pass proves the higher-order research question is solved.

These are precisely the kinds of succession errors the architecture is meant to
prevent.

## Trial return

Preserve the participant's first answers before correction.

Do not silently clean up misunderstandings in the evidence record.
